# Dashboard — scoped design router

Этот dashboard — read-only evidence workbench, не лендинг и не будущий SaaS.
Перед UI-правкой прочитай относящийся раздел `UX.md` и сохрани доказательность,
фильтры, локальную/Pages delivery boundary и рабочую плотность.

Если visual direction нового dashboard-экрана открыт, после product UX используй
`design-atlas`, затем `ui-ux-pro-max`: запиши в `UX.md` до пяти решений из
разрешённых public references, не копируя интерфейс. Текущий стек — static
HTML/CSS/JS: не добавляй React, Tailwind, shadcn или 21st ради референсов.

После реализации применяй `frontend-design`, `web-interface-guidelines`,
responsive audit/QA и `web-ui-verify`; не называй статичный screenshot proof
готовностью интерфейса.
