# Rail-протокол активного Niche Factory

Version: `1.0`
Updated: 2026-09-10

## Зачем

Этот протокол не даёт агенту превращать активный поиск ниши в новую беседу при
каждом сообщении. Единственный оперативный источник правды —
`data/ACTIVE_RUN.md`. История объясняет прошлые решения, но не определяет
текущую работу.

## Что читать перед каждым содержательным ответом

Если `data/ACTIVE_RUN.md` имеет `Status: active`, агент до анализа обязан:

1. прочитать `data/ACTIVE_RUN.md`;
2. прочитать указанный там `Source board`;
3. открыть протокол текущей macro phase;
4. только затем обрабатывать новый материал пользователя.

Новый чат, compaction или смена модели не сбрасывают активный run.

## Как классифицировать новое сообщение

| Тип сообщения | Действие | Что происходит с активным этапом |
| --- | --- | --- |
| Данные или ссылка по текущему исследованию | Проверить, сохранить provenance, обновить board | Этап продолжается либо проходит gate |
| Новый источник методологии | Встроить в канонические docs и проверки | После интеграции вернуться к прежнему этапу |
| Уточнение цели/ограничений | Обновить owner decision и затронутые этапы | Переиндексировать run, если решение реально изменилось |
| Побочная идея | Не разворачивать новый анализ | Записать только по явной просьбе в idea inbox |
| Явная команда сменить/поставить на паузу | Зафиксировать owner decision | Только тогда изменить `Status`, run или направление |
| Владелец говорит, что сейчас строится весь контур, а не исследуется домен | Поставить domain run в `parked`, сохранить resume point и перейти к system work | Не возвращать разговор к домену автоматически |

## Обязательный формат коммуникации

Каждый содержательный update активного run начинается с текущего положения:

```text
Контур: S · SCAN 2/9 — Разведка.
Проверено: какие источники и факты реально получены.
Решение: что эти данные меняют или не меняют.
Делаю сейчас: одна текущая работа агента.
От вас: максимум одно действие, только если без него нельзя двигаться.
Gate: измеримое условие перехода к следующему этапу.
```

Если этап не пройден, агент прямо пишет `не пройден` и продолжает добывать
доступные данные. Нельзя заменять незавершённую работу объяснением методологии,
новым списком идей или общим советом.

## Правила перехода

Переход разрешён, только если одновременно:

1. обновлён артефакт текущего этапа;
2. в нём есть проверяемое evidence или честный результат `нет данных`;
3. записано решение `continue`, `pivot`, `park` или `kill`;
4. обновлены `Current step`, `Current step name`, `Source board` и `Gate` в
   `data/ACTIVE_RUN.md`;
5. пользователю показан один следующий gate.

Разговор о следующем шаге без обновления состояния не считается переходом.

## Защита от «чата-болталки»

Запрещено при активном run:

* начинать поиск заново без явного решения владельца;
* выдавать идеи вне текущего этапа как новый shortlist;
* называть публичный review mining реальным CustDev;
* считать AI-аватара респондентом или его готовность купить evidence;
* переходить к продукту, лендингу или коду без соответствующего gate;
* давать несколько равноправных «следующих шагов»;
* завершать update словами «можем дальше…» без указанной текущей работы.

## Завершение или смена run

Run меняет `Status: active` только после явного owner decision либо terminal
gate. При `park`, `kill`, `complete` или смене направления создаётся worklog,
обновляется `CURRENT_STATE.md`, а старый `Source board` сохраняется как история.

`Status: parked` означает: доменный progress и следующий gate сохранены, но rail
не требует начинать ответы с этого домена и не выдаёт владельцу его action.
Возобновление возможно только по явной команде владельца.
