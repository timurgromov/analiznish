# Scoring Model — Ниши и бизнес-модели

Version: `0.7`

Эта модель создана как практический фильтр фокуса. Она не предсказывает будущее, а заставляет одинаково проверять идеи: рынок, спрос, конкуренцию, маржу, LTV, защиту, скорость денег, свободу, финансовую устойчивость и личный фокус.

Важно: наличие собственных оплат не является обязательным критерием для оценки идеи. Для новых идей почти всегда нет своих продаж. Базовая оценка строится по открытой нише: есть ли покупатели, конкуренты, спрос, референсы, понятная бизнес-модель, маржа, LTV и защита. Собственные оплаты относятся к уровню доказательности и traction, но не заменяют анализ рынка.

## Гибридная оценка ниши

Базовая модель проекта — гибридная матрица. Она не прячет все в один `Нишевой балл`, а разделяет оценку на 4 смысловых блока:

| Блок | Роль в производных показателях | Что проверяет |
| --- | ---: | --- |
| Рынок | 60% рыночной возможности | Есть ли большой сформированный рынок, спрос, конкуренция, референсы и один понятный сегмент. |
| Экономика | 40% рыночной возможности; 40% приоритета ставки | Есть ли LTV, повторные продажи, X4/маржинальность, быстрый cash cycle и деньги на реинвестирование. |
| Защита и масштаб | 35% приоритета ставки | Есть ли защита от копирования, делегируемость, переносимый актив и повторяемый канал роста. |
| Личный фильтр | 25% приоритета ставки | Подходит ли идея текущей ситуации пользователя: быстрые деньги, свобода, финансовая устойчивость и фокус. |

Эта схема сохраняет исходную методологию Власова, но не делает из нее один черный ящик. Критерии Власова разложены по блокам `Рынок`, `Экономика` и `Защита и масштаб`, а пользовательские фильтры проекта вынесены в отдельный блок `Личный фильтр`.

Каждый `deep_score` обязан давать таблицу детальных критериев. Без этой таблицы анализ считается неполным.

| Критерий | Баллы | Как оценивать |
| --- | ---: | --- |
| Сформированный рынок | 0 или 10 | Есть продавцы, покупатели, понятный спрос. Если "мы придумали то, чего нет" — 0 и hard risk. |
| Размер рынка | 0-10 | Рынок широкий, не "3,5 землекопа"; есть путь расширения по гео, сегментам или каналам. |
| Рост рынка / тренд | 0-10 | Нормализованная шкала: подтверждённое падение = 0-3, стагнация/неизвестно = 4-5, подтверждённый рост = 6-8, быстрый рост = 9-10. Если тренд не проверен, ставить не выше 5 и снижать `evidence_confidence`. |
| Горячий спрос | 0-10 | Люди ищут решение сейчас: коммерческие запросы, заявки, каталоги, объявления, активные обсуждения. |
| Конкуренция | 0-10 | Конкуренты — плюс: значит, есть деньги, спрос и референсы. Наличие сильных конкурентов не снижает `market_score`; риски отличия, канала и копирования учитываются отдельно в `Защита и масштаб` и `Канал роста`. Нет конкурентов — не плюс, а риск. |
| Референс / готовая модель | 0-10 | Есть компания/человек, кто уже зарабатывает похожим способом; понятно, как стать "крепким номером два". |
| Одна проблема / один сегмент | 0-10 | Не распыление: один широкий сегмент и одна главная боль. |
| Повторные продажи / LTV | 0-15 | Разовая продажа = 0-3, рекомендации/upsell = 4-8, повторные покупки = 9-12, подписка/расходники = 13-15. |
| Наценка X4 / маржинальность | 0-15 | X4+ = 15, X3-X4 = 10, X2-X3 = 5, ниже X2 = 0. Если маржа неизвестна — `unknown`, не ставить оптимистично. |
| Cash cycle | 0-10 | Деньги после длинного исполнения/бесплатный COGS до оплаты = 0-3, нейтральный цикл = 4-6, предоплата до основного COGS = 7-10. |
| Защита от копирования | 0-10 | Бренд, связи, доступ, данные, supply, методология, комьюнити, операционное преимущество. |
| Реинвестиционный потенциал | 0-5 | После себестоимости, налогов и маркетинга остаются деньги на рост, сайт, людей, делегирование. |
| Операционная масштабируемость | 0-10 | Можно ли делегировать производство/продажи/поддержку, не превращая бизнес в ручную занятость основателя. |
| Канал роста | 0-10 | Есть ли понятный масштабируемый acquisition: контент, реклама, партнеры, SEO, outbound, marketplace, рекомендации. |

## Детерминированный расчёт базовых блоков v0.7

До v0.7 карточки сворачивали детальные критерии в четыре блока вручную. Это позволяло гипотетической подписке или «software-марже» получить почти такой же балл, как подтверждённая экономика. Теперь каждый блок считается по одной формуле:

```text
market_score = round(100 * (
  сформированный_рынок + размер_рынка + тренд + горячий_спрос +
  конкуренция + референс + один_сегмент
) / 70)

economics_score = round(100 * (
  ltv + margin + cash_cycle + reinvestment
) / 45)

moat_scale_score = round(100 * (
  moat + operational_scale + growth_channel
) / 30)
```

Неизвестный показатель не получает оптимистичный балл:

* неизвестная маржа — не выше `5/15` без расчёта COGS;
* неподтверждённая подписка — не выше `8/15` по LTV только за сам факт recurring-модели;
* неизвестный тренд — не выше `5/10`;
* канал «можно попробовать Telegram/SEO/блогеров» без доступа и результата — не выше `3/10`;
* действующий продукт без оплат доказывает актив и исполнение, но не доказывает CAC, LTV или маржу.

`market_reference` оценивается по фактам референса. Отсутствие нашей вертикали не снижает доверие к проверенным ценам, продукту и публичной тракции референса; оно только запрещает считать `execution_priority_score` для нашей ставки.

`personal_filter_score` считается из 4 подоценок:

```text
personal_filter_score = round(0.40 * fast_money_score + 0.20 * freedom_score + 0.20 * financial_resilience_score + 0.20 * focus_score)
```

Где:

* `fast_money_score` — шанс быстро получить живые деньги;
* `freedom_score` — свобода от локации, дат, личного присутствия и жесткого календаря;
* `financial_resilience_score` — устойчивость к риску одной страны, валюты, платежного контура и платформы;
* `focus_score` — насколько идея помогает текущему фокусу и использует имеющиеся активы.

Обязательные выводы после таблицы:

* что в нише сильнее всего;
* что ломает модель;
* какие 3 данных нужно добрать, чтобы пересчитать оценку.

## Два независимых ответа вместо одного «итога»

Один общий балл оказался плохим инструментом для портфеля: он смешивает силу внешнего рынка с тем, насколько именно нам удобно и разумно сейчас запускать конкретный актив. Из-за этого готовый кодовый актив мог выглядеть выше сильного рыночного референса — хотя это не означает, что у него выше потолок бизнеса.

С версии `0.6` каждая карточка сначала получает четыре базовых блока, а затем — один или два производных показателя в зависимости от типа объекта.

| Тип объекта | Что это | Что показываем в хит-параде |
| --- | --- | --- |
| `market_reference` / рыночный референс | Чужая компания, категория или конкурент, который доказывает спрос и модель. | Только `market_opportunity_score`; это не оценка стоимости или выручки компании. |
| `concrete_bet` / конкретная ставка | Наш определённый продукт: известны клиент, оффер, канал и модель денег. | Оба показателя. |
| `existing_asset` / существующий актив | Уже созданный код, аудитория, процесс или действующий проект. | Оба показателя, но не смешивать его с референсами в одной очереди. |
| `active_business` / действующий бизнес | Бизнес с текущим исполнением и фактическими операционными данными. | Оба показателя. |

```text
market_opportunity_score = round(0.60 * market_score + 0.40 * economics_score)

execution_priority_score = round(
  (0.40 * economics_score + 0.35 * moat_scale_score + 0.25 * personal_filter_score)
  * evidence_confidence
)
```

`market_opportunity_score` отвечает на вопрос: «насколько сильны сама категория и модель заработка, если не путать их с нашими текущими активами». Он **не** умножается на доверие: низкое доверие видно отдельной колонкой и не прячет потенциально сильный рынок внизу списка.

`execution_priority_score` отвечает на другой вопрос: «стоит ли сейчас вкладывать ближайшие 7–14 дней в нашу конкретную ставку». Он учитывает экономику, защиту/масштаб, личный фильтр и качество доказательств. Его нельзя считать, пока не определены наш клиент, оффер и канал; у рыночного референса он должен быть `—`, а не искусственно низкое число.

`overall_score` версии `0.5` остаётся в старых карточках только как исторический след. С версии `0.6` он не является главным сортировочным баллом и не используется для сравнения разных типов объектов.

Базовые поля сохраняются:

* `market_score` / `Рынок` — сформированность рынка, размер, рост, спрос, конкуренция, референс и сегмент, 0-100;
* `economics_score` / `Экономика` — LTV, маржинальность, cash cycle и реинвестиционный потенциал, 0-100;
* `moat_scale_score` / `Защита и масштаб` — защита от копирования, делегируемость, переносимость актива и канал роста, 0-100;
* `personal_filter_score` / `Личный фильтр` — быстрые деньги, свобода, финансовая устойчивость и фокус, 0-100;
* `evidence_confidence` / `Доверие к оценке` — насколько можно верить баллам по текущим доказательствам, 0.40-1.00.

Неизвестное поле не получает оптимистичный балл. Если данных нет, ставь низкий score или помечай как `unverified`.

## Словарь метрик

| Русское название | Техническое поле | Что значит простыми словами | Как читать |
| --- | --- | --- | --- |
| Рыночная возможность | `market_opportunity_score` | Потенциал категории по рынку и экономике, без бонуса за наш готовый код, интерес или фокус. | Сравнивать только карту рынков; рядом всегда читать `Доверие`. |
| Приоритет ставки | `execution_priority_score` | Выгодность ближайшего вложения времени в **нашу конкретную** модель. | Сравнивать только очередь ставок. Для чужого референса — `—`. |
| Рынок | `market_score` | Есть ли большой сформированный рынок с понятным спросом, конкуренцией и референсами. | Высокий балл = идея не изобретает спрос с нуля. |
| Экономика | `economics_score` | Может ли модель зарабатывать с нормальной маржей, LTV и деньгами на рост. | Высокий балл = бизнес может кормить маркетинг, команду и делегирование. |
| Защита и масштаб | `moat_scale_score` | Насколько бизнес сложно скопировать и можно ли его масштабировать без ручного рабства. | Высокий балл = есть бренд, данные, методология, канал, процессы или переносимый актив. |
| Личный фильтр | `personal_filter_score` | Подходит ли идея именно текущей ситуации пользователя. | Высокий балл = дает шанс на быстрые деньги, свободу, устойчивость и не распыляет фокус. |
| Доверие к оценке | `evidence_confidence` | Множитель качества доказательств. | `0.82` значит: баллы выглядят неплохо, но часть данных еще не подтверждена. |
| Вердикт | `verdict` | Практическое решение по нише. | Например: `Заходить`, `Малый тест`, `Докрутить модель`, `Парковка`, `В мусорку`. |
| Главный риск | `main_risk` | Самая опасная причина, почему ниша может не сработать. | Нужен, чтобы не влюбляться в общий балл. |
| Следующий шаг | `next_action` | Самое полезное действие до следующей переоценки. | Должен быть проверяемым, а не абстрактным. |

## Пороги решения для конкретной ставки

| Приоритет ставки | Вердикт | Что делать |
| ---: | --- | --- |
| 70-100 | Фокус / масштабировать | Главная ставка с сильной экономикой и доказательствами |
| 55-69 | Денежное ядро / малый тест роста | Работать в основном фокусе, ограничивать риск следующего теста |
| 40-54 | Ограниченная валидация | Только 7–14-дневный тест продаж или канала без большой разработки |
| 25-39 | Парковка до сигнала | Не развивать; вернуться после оплаты, лида, разрешения платформы или другого сильного сигнала |
| 0-24 | Не вкладывать сейчас | Архивировать активную разработку; исследовать только при появлении новых внешних данных |

Hard filter может остановить ставку независимо от score. Низкий приоритет из-за слабой доказательности означает «не вкладывать сейчас», а не утверждение, что рынок навсегда плох. Для `market_reference` не выдавать вердикт запуска: фиксировать только силу референса, доказательства и пробелы.

## Hard Filters

Сначала проверь стоп-сигналы. Если сработал hard filter, не спасай идею баллами.

| Filter | Условие | Последствие |
| --- | --- | --- |
| Нет сформированного рынка | Нет покупателей, продавцов, конкурентов или референсов | `market_opportunity_score = 0`, статус `research`, не бизнес для быстрых денег |
| Нет конкретной модели заработка | Непонятно, кто платит, за что и как часто | Не считать `execution_priority_score` до уточнения |
| Слишком узкий рынок | Сегмент/гео выглядит как "3,5 землекопа" и нет пути расширения | `market_score <= 35`, часто `В мусорку` |
| Нет горячего спроса | Люди не ищут, не покупают и не жалуются на проблему | `market_score <= 45` и `personal_filter_score <= 55` |
| Unit economics не сходится | Маржа/чек/стоимость привлечения не оставляют денег на рост | `execution_priority_score <= 50` и не запускать масштабирование |
| Копируется без защиты | Нет бренда, канала, связей, уникального доступа, операционного преимущества | `moat_scale_score <= 55`; если это ещё и commodity без канала — `В мусорку` |
| Правовой/этический риск | Серая схема, обман, нарушение правил платформ или закона | `blocked` до отдельной проверки |

## Быстрые деньги

Оценивает, можно ли получить живые деньги быстро.

| Критерий | Баллы | Как оценивать |
| --- | ---: | --- |
| Горячий спрос и боль | 0-20 | Есть активный поиск, заявки, покупка сейчас, срочная боль |
| Speed to first cash | 0-20 | 7 дней = 20, 30 дней = 15, 60 дней = 8, дольше = 0-5 |
| Простота оффера | 0-15 | Один сегмент, одна проблема, понятный результат, понятный чек |
| Доступный канал продаж | 0-15 | Есть личный канал, партнеры, outbound, контент, реклама с понятной экономикой |
| Маржа и cash cycle | 0-15 | Деньги вперед, мало запасов, gross margin позволяет тесты |
| Личный execution fit | 0-10 | Есть навыки, активы, контакты, скорость производства |
| Низкое операционное трение | 0-5 | Нет сложной логистики, лицензий, найма, долгого внедрения |

## Фокус

Оценивает, насколько идея помогает не распыляться.

| Критерий | Баллы | Как оценивать |
| --- | ---: | --- |
| Совпадение с текущими активами | 0-20 | Навыки, аудитория, кейсы, код, связи, рынок |
| Малый тест без большой ставки | 0-20 | Можно проверить до крупных вложений |
| Низкая стоимость отвлечения | 0-20 | Не ломает текущие проекты и денежный поток |
| Синергия с другими проектами | 0-20 | Усиливает существующие активы |
| Личная энергия без самообмана | 0-20 | Интерес есть, но не заменяет доказательства рынка |

## Свобода

Оценивает, насколько бизнес-модель дает свободу перемещения, времени и операционного контроля.

| Критерий | Баллы | Как оценивать |
| --- | ---: | --- |
| Географическая независимость | 0-25 | Можно работать из любой страны = 25, нужен конкретный город/офлайн = 0-5 |
| Независимость от дат и календаря | 0-20 | Асинхронная/evergreen модель = 20, жесткие события/слоты = 0-5 |
| Низкая зависимость от личного присутствия | 0-20 | Можно делегировать или автоматизировать = 15-20, без основателя не продается/не исполняется = 0-5 |
| Операционная гибкость | 0-15 | Нет склада, офиса, сложной логистики, лицензий, тяжелых встреч |
| Портативность активов | 0-20 | Код, контент, аудитория, бренд, процессы и данные можно перенести между рынками/гео |

## Финансовая устойчивость

Оценивает не размер дохода, а защищенность денежного потока от локальных рисков.

| Критерий | Баллы | Как оценивать |
| --- | ---: | --- |
| Валютность дохода | 0-25 | USD/EUR/global revenue = 20-25, только рубли/локальный рынок = 0-8 |
| Географическая диверсификация клиентов | 0-20 | Клиенты из нескольких стран/рынков = 15-20, один город/страна = 0-8 |
| Платежная и юридическая устойчивость | 0-20 | Есть легальные платежные варианты, понятные налоги/контуры, низкий risk of account lock |
| Независимость от одного канала/платформы | 0-15 | Несколько каналов продаж/монетизации, нет единственной платформы-арбитра |
| Сценарная выживаемость | 0-20 | Бизнес переживает переезд, блокировки, падение локального спроса, валютные шоки |

## Доверие к оценке

Множитель качества доказательств:

| Доверие | Условие |
| ---: | --- |
| 1.00 | Есть проверенный рынок, конкуренты, цены, спрос, unit economics и собственные или надежно подтвержденные продажи |
| 0.85 | Есть конкуренты, цены, search demand, понятный канал и расчет unit economics; собственных продаж может еще не быть |
| 0.70 | Есть публичные признаки, конкуренты и расчет, но мало первичных данных по спросу/марже/CAC |
| 0.55 | Идея в основном на гипотезах, источники не проверены |
| 0.40 | Почти чистая фантазия, AI-синтез без корпуса или тренд без понятной монетизации |

Для `quick_scan` без web/Wordstat/конкурентной проверки confidence обычно не выше `0.55`.

### Evidence caps Niche Discovery Loop v1.0

Для новых и переоцениваемых конкретных ставок действует лестница из
`docs/NICHE_DISCOVERY_LOOP.md`:

| Strongest evidence | Сигнал | Максимум confidence |
| --- | --- | ---: |
| E0 | Идея, AI-аватар, synthetic interview без реального корпуса | 0.40 |
| E1 | Проверенный desk research | 0.55 |
| E2 | Реальные интервью о прошлом поведении | 0.70 |
| E3 | Действие клиента: интро, данные, demo, LOI | 0.80 |
| E4 | Оплата, платный пилот или подтверждённый бюджет | 0.90 |
| E5 | Повтор, retention и фактическая экономика | 1.00 |

Это caps, а не автоматически выдаваемые значения. Слабое качество выборки,
конфликтующие данные или неизвестная экономика могут потребовать более низкого
confidence. Количество интервью/отзывов не позволяет перейти на следующий
уровень без более сильного поведения.

Портфельные confidence, рассчитанные до 2026-09-08, являются legacy v0.7 и не
пересчитываются механически без повторного чтения карточки. При следующем
`rescore` каждая такая ставка обязана получить `validation_stage`, E-level и
новый cap; до этого старое число нельзя читать как прохождение build gate.

## Методика емкости рынка

Используй TAM/SAM/SOM:

* `TAM` — весь потенциальный рынок категории;
* `SAM` — достижимая часть рынка с учетом географии, канала, языка, сегмента;
* `SOM` — реалистичная доля, которую можно забрать в горизонте 12-36 месяцев.

Минимальная формула:

```text
TAM = количество потенциальных покупателей * средний годовой чек
SAM = TAM * доля достижимого сегмента
SOM = SAM * реалистичная доля захвата
```

Если нет данных, делай 3 сценария:

* conservative;
* base;
* aggressive.

Ниша получает штраф, если даже aggressive-сценарий не дает интересного денежного результата.

## Wordstat / Trends Logic

Для русскоязычных и российских ниш в приоритете Яндекс Вордстат. Для глобальных или англоязычных ниш — Google Trends и SERP.

Оцени:

* прямые коммерческие запросы;
* информационные запросы вокруг боли;
* региональность;
* сезонность;
* динамику за 12-24 месяца;
* related queries;
* наличие рекламы и конкурентов в выдаче.

Trend score:

| Динамика | Raw trend | Score contribution |
| --- | ---: | ---: |
| Сильный рост | +10 | 10 |
| Умеренный рост | +5 | 8 |
| Flat / сезонность без роста | 0 | 5 |
| Умеренное падение | -5 | 2 |
| Умирающий спрос | -10 | 0 |

Google Trends не дает абсолютный спрос, только относительный интерес. Не используй его как единственный источник размера рынка.

## Core Checks

Из транскрибации, которую дал пользователь, в проекте закреплены проверки. Они не должны быть спрятаны внутри общих баллов — они выводятся отдельной таблицей в каждом отчете:

* рынок уже сформирован;
* конкуренция — плюс, а не минус;
* не писать "рынок занят" как причину низкого рыночного балла: занятость сильными игроками доказывает рынок; снижать можно только защиту, канал, дифференциацию или доверие к оценке;
* нужна широкая емкость, не "3,5 землекопа";
* спрос должен быть горячим;
* модель лучше брать с референса и становиться крепким номером два;
* одна проблема — один широкий сегмент;
* повторные продажи/LTV важнее разовых продаж;
* наценка X4 — сильный плюс для роста;
* нужна защита: бренд, связи, канал, supply, operations;
* изъятие всей прибыли из бизнеса ухудшает шанс масштабирования.

Дополнения проекта:

* рост рынка / тренд: выбирать рынки, которые растут, а не сжимаются;
* операционная масштабируемость: можно ли делегировать и стандартизировать бизнес;
* канал роста: есть ли повторяемый способ привлекать клиентов/аудиторию;
* свобода: насколько бизнес отвязан от локации, дат и личного присутствия;
* финансовая устойчивость: насколько доход защищен от одной страны, валюты, платежного контура и платформы;
* личный фокус: не является ли идея очередным распылением.

## Caps And Penalties

Применяй caps после суммирования:

| Условие | Cap |
| --- | ---: |
| Нет референса/конкурента | `market_opportunity_score <= 40`; не считать ставку готовой к запуску |
| Нет повторных продаж | `economics_score <= 70` |
| Маржа ниже X2 | `economics_score <= 60` |
| Нет канала привлечения | `moat_scale_score <= 60` и `personal_filter_score <= 60` |
| Нет защиты и модель легко копируется | `moat_scale_score <= 55` |
| Полная привязка к месту/датам/основателю | `personal_filter_score <= 65`, если свобода важна для текущей стратегии |
| Доход только в одном локальном рынке и одной валюте | `personal_filter_score <= 65`, если валютная/гео-устойчивость важна для текущей стратегии |
| Нет личного fit и требуется новая экспертиза | `personal_filter_score <= 50` |
