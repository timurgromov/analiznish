# Worklog

Рабочая летопись проекта. Записи фиксируют не просто diff, а намерение, контекст, проверки и результат.

## Имя файла

```text
YYYY-MM-DD-short-topic.md
```

## Шаблон записи

```md
# YYYY-MM-DD — short topic

## Intent

Что хотели изменить или понять.

## Context

Почему задача возникла. Симптомы, риски, ограничения.

## Changes

- Что реально поменялось.
- Какие файлы/данные/runtime затронуты.

## Verification

- Локально:
- Production/VPS/staging:
- Тесты:

## Result

Что теперь считается сделанным.

## Risks / Follow-up

- Что осталось непроверенным.
- Что может сломаться.
- Что нужно сделать позже.

## Links

- Commit:
- PR:
- Deploy:
- Related decisions:
```
